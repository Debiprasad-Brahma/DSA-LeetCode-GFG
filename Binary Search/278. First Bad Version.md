## 🧪 LeetCode 278 — First Bad Version | Binary Search on Versions

### 💡 Intuition  
Versions are ordered from `1` to `n`.  
Once a version becomes **bad**, all versions after it are also bad.

This creates a **monotonic condition**:
- `false false false ... true true true`

Our goal is to find the **first occurrence of `true`**, which is a classic **binary search** problem.

---

### 🧠 Approach  
1. Initialize:
   - `start = 1`
   - `end = n`
   - `ans = n` (worst-case fallback)
2. Perform binary search:
   - If `mid` is bad:
     - Save it as a potential answer
     - Search left half (`end = mid - 1`)
   - Else:
     - Search right half (`start = mid + 1`)
3. When search ends, `ans` contains the first bad version.

This minimizes API calls and runs efficiently.

---

### ⏱️ Complexity  
- **Time Complexity:** O(log n) — binary search  
- **Space Complexity:** O(1)

---

### 💻 Code  
```java
/* The isBadVersion API is defined in the parent class VersionControl.
      boolean isBadVersion(int version); */

public class Solution extends VersionControl {

    public int firstBadVersion(int n) {
        int start = 1;
        int end = n;
        int ans = n;

        while (start <= end) {
            int mid = start + (end - start) / 2;

            if (isBadVersion(mid)) {
                ans = mid;        // possible first bad version
                end = mid - 1;    // search earlier versions
            } else {
                start = mid + 1;  // search later versions
            }
        }
        return ans;
    }
}
