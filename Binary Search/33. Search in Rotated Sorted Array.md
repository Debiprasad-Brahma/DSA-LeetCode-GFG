## 🔄 LeetCode 33 — Search in Rotated Sorted Array | Modified Binary Search

### 💡 Intuition  
The array was originally **sorted**, but then **rotated at some pivot**.  
Despite rotation, **one half of the array is always sorted**.

At every step of binary search:
- Either the **left half** is sorted
- Or the **right half** is sorted

We can use this property to decide **which half to discard**.

---

### 🧠 Approach  
1. Use standard binary search pointers: `start`, `end`.
2. Calculate `mid`.
3. If `nums[mid] == target` → return `mid`.
4. Check which half is sorted:
   - **Left half sorted** (`nums[start] <= nums[mid]`)
     - If `target` lies within this range → search left
     - Else → search right
   - **Right half sorted**
     - If `target` lies within this range → search right
     - Else → search left
5. If target is not found, return `-1`.

---

### ⏱️ Complexity  
- **Time Complexity:** O(log n)  
- **Space Complexity:** O(1)

---

### 💻 Code  
```java
class Solution {

    public int search(int[] nums, int target) {
        int n = nums.length;
        int start = 0;
        int end = n - 1;

        while (start <= end) {
            int mid = start + (end - start) / 2;

            if (nums[mid] == target) return mid;

            // Left half is sorted
            if (nums[start] <= nums[mid]) {
                if (nums[start] <= target && target < nums[mid]) {
                    end = mid - 1;
                } else {
                    start = mid + 1;
                }
            }
            // Right half is sorted
            else {
                if (nums[mid] < target && target <= nums[end]) {
                    start = mid + 1;
                } else {
                    end = mid - 1;
                }
            }
        }
        return -1;
    }
}
