# 🔥 Merge Intervals | In-Place O(N log N) | No Extra List | Write-Back Pointer Trick | Must-Know Pattern

---

## 💡 Intuition

The naive approach uses an extra `ArrayList`, adds merged intervals, then converts back to array — works but wastes space and clarity.

> Key Insight: After **sorting by start time**, overlapping intervals are always **adjacent**. So we can merge them in-place using a **write pointer `k`** that tracks the last merged interval's position.

Think of it like **compressing a timeline** — once sorted, you just keep extending the current block as long as the next event overlaps, otherwise start a new block.

> 🎯 The write-pointer `k` technique is what makes this solution stand out — no extra ArrayList, merging directly into the input array.

---

## 🧠 Approach — Sort + In-Place Write Pointer

1. **Sort** intervals by start time.
2. Set write pointer `k = 0` (last confirmed merged interval).
3. For each interval `i`:
   - If `intervals[k][1] >= intervals[i][0]` → **overlap** → extend end: `intervals[k][1] = max(intervals[k][1], intervals[i][1])`
   - Else → **no overlap** → advance `k`, write `intervals[k] = intervals[i]`
4. Copy first `k+1` intervals into result array.
5. Return result.

---

## 📊 Dry Run

```
intervals = [[1,3],[2,6],[8,10],[15,18]]
```

**After Sort:** `[[1,3],[2,6],[8,10],[15,18]]` (already sorted)

---

| i | curr interval | intervals[k] | Overlap? | Action | k |
|---|---------------|--------------|----------|--------|---|
| 0 | [1,3]         | [1,3]        | —        | Initial state (k=0, i=0 same) | 0 |
| 1 | [2,6]         | [1,3]        | ✅ 3>=2   | extend → [1, max(3,6)] = [1,6] | 0 |
| 2 | [8,10]        | [1,6]        | ❌ 6<8    | k++ → write [8,10] at k=1 | 1 |
| 3 | [15,18]       | [8,10]       | ❌ 10<15  | k++ → write [15,18] at k=2 | 2 |

**Result array (k+1 = 3 intervals):**
```
[[1,6],[8,10],[15,18]]  ✅
```

## 📊 Dry Run — Fully Overlapping Case

```
intervals = [[1,4],[2,3]]
```

**After Sort:** `[[1,4],[2,3]]`

| i | curr   | intervals[k] | Overlap?   | Action |
|---|--------|--------------|------------|--------|
| 0 | [1,4]  | [1,4]        | —          | Initial |
| 1 | [2,3]  | [1,4]        | ✅ 4>=2     | extend → [1, max(4,3)] = **[1,4]** |

> 💡 `Math.max` on end handles the case where new interval is **fully contained** inside current — end stays unchanged. 

**Output:** `[[1,4]]` ✅

## 🧪 Edge Cases

```
intervals = [[1,4]]              →  [[1,4]]              (single interval)
intervals = [[1,4],[5,6]]        →  [[1,4],[5,6]]        (no overlap, touch but don't merge)
intervals = [[1,4],[4,6]]        →  [[1,6]]              (touching → merge, 4>=4 ✅)
intervals = [[1,4],[2,3]]        →  [[1,4]]              (fully contained)
intervals = [[1,10],[2,6],[8,9]] →  [[1,10]]             (all inside one)
intervals = []                   →  []                   (empty)
```

## ✅ Code (Java)

```java
class Solution {
    public int[][] merge(int[][] intervals) {

        // Step 1: Sort by start time — overlapping intervals become adjacent
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));

        int k = 0;    // Write pointer → last confirmed merged interval index

        for (int i = 0; i < intervals.length; i++) {
            int start = intervals[i][0];
            int end   = intervals[i][1];

            if (intervals[k][1] >= start) {
                // Overlap → extend current interval's end if needed
                intervals[k][1] = Math.max(intervals[k][1], end);
            } else {
                // No overlap → move write pointer forward, place new interval
                k++;
                intervals[k] = intervals[i];
            }
        }

        // Step 2: Copy only the first k+1 merged intervals
        int[][] result = new int[k + 1][];
        for (int i = 0; i <= k; i++) {
            result[i] = intervals[i];
        }

        return result;
    }
}
```

## ⏱ Complexity Analysis

| | Complexity | Reason |
|---|---|---|
| **Time** | O(N log N) | Dominated by sorting; merge pass = O(N) |
| **Space** | O(1) | No extra list — write directly into input array |

> 💡 The output array `result` is O(N) in worst case (no overlaps), but that's **output space** — not auxiliary space. In-place working space = O(1).

---

## 🔑 Why `intervals[k][1] >= start` and not `> start`?

```
intervals = [[1,4],[4,6]]

intervals[k][1] = 4,  start = 4
4 >= 4  →  ✅ OVERLAP → merge to [1,6]

If we used strictly > :
4 > 4   →  ❌ NO OVERLAP → [[1,4],[4,6]]  WRONG!

Touching intervals (sharing endpoint) ARE considered overlapping.
The >= handles this boundary case correctly.
```

---

## 🔑 Why `Math.max` on End?

```
Without Math.max:
    Current = [1,10],  New = [2,4]
    intervals[k][1] = 4  ← WRONG! Shrunk the interval!

With Math.max:
    intervals[k][1] = max(10, 4) = 10  ✅ Fully contained case handled
```

## ⚔️ In-Place Write Pointer vs ArrayList Approach

| | **In-Place (This Solution)** ✅ | **ArrayList Approach** |
|---|---|---|
| **Space** | O(1) auxiliary | O(N) for the list |
| **Code length** | Compact | Slightly more verbose |
| **Mutates input** | Yes | No |
| **Interview signal** | Advanced pointer technique | Standard approach |
| **Readability** | Needs explanation | More intuitive |

### ArrayList Approach (Safer to Explain in Interviews):
```java
List<int[]> result = new ArrayList<>();
Arrays.sort(intervals, (a, b) -> a[0] - b[0]);

for (int[] interval : intervals) {
    if (result.isEmpty() || result.get(result.size()-1)[1] < interval[0]) {
        result.add(interval);                              // No overlap → add new
    } else {
        result.get(result.size()-1)[1] =
            Math.max(result.get(result.size()-1)[1], interval[1]);  // Overlap → extend
    }
}
return result.toArray(new int[result.size()][]);
```

> 🎯 **Interview tip:** Start with ArrayList for clarity, then mention the in-place write-pointer approach as an O(1) space optimization — shows both correctness and optimization thinking!

## 🚨 Common Mistakes to Avoid

```
❌  Sorting by end instead of start → wrong adjacency order
❌  Using > instead of >= for overlap check → misses touching intervals [1,4],[4,6]
❌  Not using Math.max on end → fully contained intervals shrink the result
❌  Returning intervals directly without slicing → includes stale unmerged intervals
❌  Starting loop at i=1 to skip i=0 → causes ArrayIndexOutOfBounds when k=0, i=0 overlap check
```

## 📌 Key Takeaways (Revision Flashcard)

- 🟡 **Sort by start** → overlapping intervals become adjacent → single pass merge
- 🟡 **Write pointer `k`** → in-place merge, no extra list needed
- 🟡 **Overlap condition:** `intervals[k][1] >= start` → `>=` handles touching endpoints
- 🟡 **`Math.max` on end** → handles fully contained intervals correctly
- 🟡 **Output size = `k+1`** → slice first k+1 elements from modified input
- 🟡 Time: **O(N log N)** | Space: **O(1)** auxiliary
