# 🎯 Combination Sum II | Backtracking with Duplicate Handling (Java)

## 📘 Problem Statement
Given a collection of candidate numbers `candidates` (**may contain duplicates**) and a target integer `target`,  
find all **unique combinations** in `candidates` where the chosen numbers sum to `target`.

Each number in `candidates` **may only be used once** in each combination.  
Return the combinations in any order.

---

## 💡 Intuition
Unlike **Combination Sum I**, where each element can be used unlimited times,  
in **Combination Sum II** we can use each number **only once** — and we must handle **duplicates** carefully.

To avoid repeating the same combinations:
- Sort the array first.
- While exploring choices, skip any duplicate elements at the same recursion level.

This ensures combinations like `[1,2,2]` are added once even if duplicates exist in the input.

---

## ⚙️ Approach
1. **Sort** the input array to easily detect and skip duplicates.
2. Use a **recursive backtracking** function `findCombinations()`:
   - **Base Case:**  
     If `target == 0`, add the current list to the result.
   - **Iterate** over the array from the given index:
     - **Skip duplicates**: If the current element equals the previous one and `i > idx`, continue.
     - **Prune**: If `candidates[i] > target`, break the loop since all further elements will also be too large.
     - **Include** the number and recurse with `i + 1` (each number used only once).
     - **Backtrack** by removing the last added number.
3. Return all stored valid combinations.

---

# 🌳 Recursion Flow (Simplified)
                              (target=8, idx=0)
                            /        |         \
                         pick 1    skip 1      pick 2
                          |                     |
                   (target=7, idx=1)       (target=6, idx=3)
                   /        \                    \
               pick 1     skip 1               pick 6 ✅
                |             \
        (target=6, idx=2)     pick 7 ✅
          |
       pick 2 ✅
---
# ⏱️ Complexity Analysis
* Time Complexity	**O(2^n)** — In the worst case, each element can either be included or excluded, leading to exponential growth. Sorting adds **O(n log n)** initially, which is negligible compared to recursion.
* Space Complexity	**O(n)** — Due to recursion stack depth and temporary list for building combinations.
---
# Code
```java []
class Solution {

    void findCombinations(int idx, int[] candidates, int target, List<List<Integer>> ans, List<Integer> ds){
        if (target == 0) {
            ans.add(new ArrayList<>(ds));
            return;
        }

        for (int i = idx; i < candidates.length; i++) {
            // Skip duplicate numbers at the same level
            if (i > idx && candidates[i] == candidates[i - 1]) continue;

            // Stop if current number exceeds the remaining target
            if (candidates[i] > target) break;

            ds.add(candidates[i]);
            findCombinations(i + 1, candidates, target - candidates[i], ans, ds); // move to next index
            ds.remove(ds.size() - 1);
        }
    }
    public List<List<Integer>> combinationSum2(int[] candidates, int target) {
        Arrays.sort(candidates);
        List<List<Integer>> ans = new ArrayList<>();
        findCombinations(0, candidates, target, ans, new ArrayList<>());
        return ans;
    }
}
```
