## ⚡ LeetCode 45 — Jump Game II | Greedy Level-Based Jumping

### 💡 Intuition  
We need the **minimum number of jumps** to reach the last index.  
This is a classic greedy problem where each “jump” can be seen as expanding your reachable range.

We maintain:
- `maxLen` → the farthest we can reach from explored indices  
- `currLen` → the boundary of the current jump  
- `jump` → total jumps taken so far  

Whenever we reach the end of the current jump boundary (`i == currLen`),  
we **increase the jump count** and move the boundary to `maxLen`.

This mimics **level traversal** in BFS—but done greedily and efficiently.

---

### 🧠 Approach  
1. Initialize:
   - `maxLen = 0` (max reach so far)  
   - `currLen = 0` (current jump boundary)  
   - `jump = 0` (jump counter)
2. Iterate from index `0` to `n-2`:
   - Update `maxLen = max(maxLen, i + nums[i])`.
   - When you reach the boundary (`i == currLen`):
     - You must make a jump → `jump++`
     - Update the boundary → `currLen = maxLen`
3. Return the number of jumps.

Note: You never need to check the last index because reaching or passing it is enough.

---

### ⏱️ Complexity  
- **Time Complexity:** O(n) — single pass  
- **Space Complexity:** O(1) — constant extra variables

---

### 💻 Code  
```java
class Solution {

    public int jump(int[] nums) {
        int n = nums.length;
        int currLen = 0;
        int maxLen = 0;
        int jump = 0;

        for (int i = 0; i < n - 1; i++) {
            maxLen = Math.max(maxLen, i + nums[i]);

            if (i == currLen) {
                jump++;
                currLen = maxLen;
            }
        }

        return jump;
    }
}
