## 🔁 LeetCode 991 — Broken Calculator | Reverse Greedy Recursion

### 💡 Intuition  
The calculator allows only:
- **Double (x2)**
- **Decrement (-1)**

But doing this **forward** from `startValue` is inefficient.  
Instead, we work **backward from `target`**, reversing operations:

- If the target is **even**, the previous state must have been `target / 2` (reverse of ×2).
- If the target is **odd**, the previous state must have been `target + 1` (reverse of -1 operation).
- If `startValue >= target`, the only way is decreasing: `startValue - target`.

This greedy reverse logic guarantees minimal steps.

---

### 🧠 Approach  
1. If `startValue >= target`, we only need `(startValue - target)` decrements.  
2. If `target` is **even**, reverse the doubling:  
   → recurse on `target / 2`  
3. If `target` is **odd**, reverse the decrement:  
   → first make it even by going to `target + 1`

Each reverse operation counts as one step.

---

### ⏱️ Complexity  
- **Time Complexity:** O(log target) — each step halves or increments target  
- **Space Complexity:** O(log target) — recursion depth

---

### 💻 Code  
```java
class Solution {

    public int brokenCalc(int startValue, int target) {
        if (startValue >= target) return startValue - target;

        // If target is even, reverse the "double" operation
        if (target % 2 == 0) {
            return 1 + brokenCalc(startValue, target / 2);
        }

        // If target is odd, reverse the "decrement" by doing target + 1
        return 1 + brokenCalc(startValue, target + 1);
    }
}
