# 💡 Intuition (Plain Thinking)  
We are looking for a **132 pattern**, i.e. indices `i < j < k` such that: 
nums[i] < nums[k] < nums[j]

Instead of fixing all three positions (which is messy and slow), it’s much easier to:
- Fix the **middle value (3)**
- Try to find a valid **2** and **1** around it

The trick is to scan the array **from right to left**.

---

# 🧠 How the Idea Comes Naturally  
When scanning from the right:
- The stack helps us track **possible "3" values**
- A variable `secLar` (second largest) keeps track of the best candidate for **"2"**
- If at any point we find a number **smaller than `secLar`**, we have:
1 < 2 < 3

So the plan becomes:
- Maintain a **decreasing stack**
- Pop elements when we find a bigger number
- Update `secLar` as we pop

---

# 🧩 Step-by-Step Logic  
1. Traverse the array from **right to left**
2. If current number `< secLar`
 - We found a valid **1**
 - Pattern exists → return `true`
3. While stack is not empty and:
nums[i] > stack.peek()
- Pop from stack
- Update `secLar` (this becomes the "2")
4. Push current number to the stack
5. If loop ends, no pattern exists

---

# ⏱️ Complexity  
- **Time Complexity:** O(n)  
- Each element is pushed and popped once
- **Space Complexity:** O(n)  
- Stack usage

# Code
```java []
class Solution {

    public boolean find132pattern(int[] nums) {
        int n = nums.length;
        Stack<Integer> stk = new Stack<>();
        int secLar = Integer.MIN_VALUE;

        for (int i = n - 1; i >= 0; i--) {
            if (nums[i] < secLar) {
                return true;
            }

            // if found keep updating secLar
            while (!stk.isEmpty() && nums[i] > stk.peek()) {
                secLar = stk.pop();
            }
            stk.push(nums[i]);
        }
        return false;
    }
}

```
