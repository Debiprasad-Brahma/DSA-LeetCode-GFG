# 🔥 Rotate List | Make Circular + Re-Break O(N) | No Extra Space | Handles All Edge Cases

---

## 💡 Intuition

Rotating right by `k` means the **last `k` nodes jump to the front**.  
Naively shifting one node at a time = **O(N·K)** — way too slow for large `k`.

> Key Insight: Instead of physically moving nodes `k` times, **make the list circular** first, then find exactly where to "cut" it.  
> The new head is at position `(size - k)` from the original head.

Think of it like a **clock** — instead of rotating hands one tick at a time, find the final position directly and reset from there.

> ⚠️ **Critical Observation:** Rotating by `k = size` brings the list back to itself.  
> So we only ever need `k = k % size` — the **effective rotation**.

---

## 🧠 Approach — Make Circular, Find Cut Point

1. **Guard:** null, single node, or `k == 0` → return as is.
2. **Find size + tail:** Traverse to get length and land on last node.
3. **Effective rotation:** `k = k % size` — if `k == 0` after this → return as is.
4. **Make circular:** `last.next = head`.
5. **Find new tail:** Walk `size - k - 1` steps from head → this is the new tail.
6. **Re-break:** `head = newTail.next`, `newTail.next = null`.
7. Return new `head`.

## 📊 Dry Run

```
head = 1 → 2 → 3 → 4 → 5,   k = 2
```

**Step 1 — Find size & tail:**
```
size = 5,  last = node(5)
```

**Step 2 — Effective k:**
```
k = 2 % 5 = 2  (no change here)
```

**Step 3 — Make Circular:**
```
1 → 2 → 3 → 4 → 5
↑___________________↓
```

**Step 4 — Find new tail (walk size - k - 1 = 5 - 2 - 1 = 2 steps):**
```
Start at node(1)
Step 1 → node(2)
Step 2 → node(3)   ← new tail
```

**Step 5 — Re-break:**
```
head     = node(3).next = node(4)
node(3).next = null
```

**Output:** `4 → 5 → 1 → 2 → 3` ✅

## 🧪 Edge Cases

```
head = null             →  null             (empty list)
head = [1]              →  [1]              (single node)
k = 0                   →  head unchanged   (no rotation)
k = size                →  head unchanged   (full rotation = no-op)
k = 2*size              →  head unchanged   (k % size = 0)
head = [1,2], k = 1     →  [2,1]
head = [1,2], k = 3     →  [2,1]            (k%2 = 1)
```

## ✅ Code (Java)

```java
class Solution {
    public ListNode rotateRight(ListNode head, int k) {

        // Guard: empty, single node, or no rotation needed
        if (head == null || head.next == null || k == 0) return head;

        // Step 1: Find size and reach the last node
        ListNode last = head;
        int size = 1;
        while (last.next != null) {
            last = last.next;
            size++;
        }

        // Step 2: Effective rotation — rotating by full size = no-op
        k = k % size;
        if (k == 0) return head;

        // Step 3: Make the list circular
        last.next = head;

        // Step 4: Walk to the new tail (size - k - 1 steps from head)
        ListNode newTail = head;
        for (int i = 0; i < size - k - 1; i++) {
            newTail = newTail.next;
        }

        // Step 5: Re-break the circle
        head = newTail.next;    // New head = node at position (size - k)
        newTail.next = null;    // New tail ends the list

        return head;
    }
}
```

## ⏱ Complexity Analysis

| | Complexity | Reason |
|---|---|---|
| **Time** | O(N) | One pass to find size + one pass of at most N steps to find cut |
| **Space** | O(1) | Only pointer variables — no extra storage |

> 💡 Total steps = at most **2N** (size traversal + cut-point traversal) → still O(N).

---

## 🔑 Why `size - k - 1` Steps? (The Math Interviewers Ask)

```
List indices (0-based):  0   1   2   3   4
Nodes:                   1 → 2 → 3 → 4 → 5    size = 5, k = 2

New head should be at index:  size - k     = 5 - 2 = 3  → node(4)
New tail should be at index:  size - k - 1 = 5 - 2 - 1 = 2  → node(3)

So walk (size - k - 1) steps from head to land on new tail ✅
```

## ⚔️ All Approaches Compared

| Approach | Time | Space | Idea |
|---|---|---|---|
| **Make Circular + Re-break** ✅ | O(N) | O(1) | This solution |
| **Two Pointer (Fast-Slow)** | O(N) | O(1) | Fast pointer k steps ahead, both walk to end |
| **Array Copy** | O(N) | O(N) | Flatten to array, rotate, rebuild list |
| **Naive Shift** | O(N·K) | O(1) | Move last node to front, repeat k times |

### Two Pointer Approach (Alternative Clean Solution):
```java
// Fast pointer starts k steps ahead of slow
// When fast reaches tail → slow is at new tail

ListNode fast = head, slow = head;
int size = 1;
while (fast.next != null) { fast = fast.next; size++; }

k = k % size;
if (k == 0) return head;

fast.next = head;                       // Make circular
for (int i = 0; i < size - k - 1; i++) slow = slow.next;

head = slow.next;                       // New head
slow.next = null;                       // Break circle
return head;
```

## 🚨 Common Mistakes to Avoid

```
❌  Forgetting k % size → causes index out of range or infinite loop
❌  Not handling k == 0 after modulo → wastes O(N) traversal
❌  Walking size - k steps instead of size - k - 1 → lands on new head, not new tail
❌  Forgetting to set newTail.next = null → list stays circular, causes infinite loops
```

---

## 📌 Key Takeaways (Revision Flashcard)

- 🟡 **`k = k % size`** always first — effective rotation, prevents unnecessary work
- 🟡 **Make circular** = connect tail to head, enabling seamless re-breaking
- 🟡 **New tail** is at index `size - k - 1` (0-based) from original head
- 🟡 **New head** is `newTail.next` — always set `newTail.next = null` after!
- 🟡 **Two traversals max** = finding size + finding cut point → O(N) total
- 🟡 Time: **O(N)** | Space: **O(1)**
