# 🔥 Odd Even Linked List | In-Place Rewiring O(N) | No Extra Space | Clever Single-Pass Approach

---

## 💡 Intuition

The naive approach copies values into arrays, rearranges, and writes back — defeats the purpose of linked lists.

> Key Insight: We don't need two separate lists. We can **rewire pointers in-place** — for each iteration, grab the next odd-positioned node and stitch it right after the current odd node, while keeping `evenHead` as an anchor to reconnect evens.

Think of it like a train — instead of rebuilding it from scratch, you **uncouple the odd coaches and reattach them to the front half**, while the even coaches naturally group at the back.

> ⚠️ **Note:** This is a more compact approach than the classic two-pointer split.  
> Both are O(N) time, O(1) space — but this rewires **in-place per step** rather than building two full separate chains.

---

## 🧠 Approach — In-Place Pointer Rewiring

1. Guard: if `head == null` or single node → return as is.
2. Set `odd = head`, `evenHead = head.next`, `even = head.next`.
3. Each iteration (while `even != null && even.next != null`):
   - `odd.next = even.next` → skip even, point odd to next odd node
   - `even.next = odd.next.next` → skip odd, point even to next even node
   - `odd.next.next = evenHead` → reattach entire even chain after new odd
   - Advance: `odd = odd.next`, `even = even.next`
4. Return `head`.

## 📊 Dry Run

```
Input: 1 → 2 → 3 → 4 → 5
```

**Initial State:**
```
odd = 1,  even = 2,  evenHead = 2
List: 1 → 2 → 3 → 4 → 5
```

---

**Iteration 1:**
```
odd.next     = even.next      →  1.next = 3        (1 → 3)
even.next    = odd.next.next  →  2.next = 4        (2 → 4)
odd.next.next = evenHead      →  3.next = 2        (3 → 2 → 4 → 5)

List now: 1 → 3 → 2 → 4 → 5
odd = 3,  even = 4
```

---

**Iteration 2:**
```
odd.next     = even.next      →  3.next = 5        (3 → 5)
even.next    = odd.next.next  →  4.next = null     (4 → null)
odd.next.next = evenHead      →  5.next = 2        (5 → 2 → 4 → null)

List now: 1 → 3 → 5 → 2 → 4 → null
odd = 5,  even = null
```

---

**Loop ends → Return head**

```
Output: 1 → 3 → 5 → 2 → 4  ✅
```

## 🧪 Edge Cases

```
head = null              →  null         (empty list)
head = [1]               →  [1]          (single node)
head = [1,2]             →  [1,2]        (no change needed)
head = [2,1]             →  [2,1]        (already grouped)
head = [1,2,3,4]         →  [1,3,2,4]   (even length)
head = [1,2,3,4,5,6]     →  [1,3,5,2,4,6]
```

## ✅ Code (Java)

```java
class Solution {
    public ListNode oddEvenList(ListNode head) {

        // Guard: 0 or 1 node → nothing to rearrange
        if (head == null || head.next == null) return head;

        ListNode odd     = head;           // Tracks current odd-position node
        ListNode evenHead = head.next;     // Anchor for even chain (never moves)
        ListNode even    = head.next;      // Tracks current even-position node

        while (even != null && even.next != null) {
            odd.next       = even.next;        // odd → next odd node (skip even)
            even.next      = odd.next.next;    // even → next even node (skip odd)
            odd.next.next  = evenHead;         // reattach full even chain after odd

            odd  = odd.next;                   // advance odd pointer
            even = even.next;                  // advance even pointer
        }

        return head;    // head (first odd node) unchanged
    }
}
```

## ⏱ Complexity Analysis

| | Complexity | Reason |
|---|---|---|
| **Time** | O(N) | Single pass — each node visited exactly once |
| **Space** | O(1) | Only 3 pointers — no extra data structures |

> 💡 `evenHead` is the secret weapon — it never moves but always knows where the even chain starts, allowing re-stitching in O(1) per step.

---

## ⚔️ This Approach vs Classic Two-Chain Approach

| | **This Solution (In-Place)** | **Classic Two-Chain** |
|---|---|---|
| **Strategy** | Rewire per step, keep `evenHead` anchor | Build separate odd/even chains, join at end |
| **Time** | O(N) | O(N) |
| **Space** | O(1) | O(1) |
| **Pointer ops/step** | 3 reassignments + advance | 2 reassignments + advance |
| **Readability** | Trickier to trace | More intuitive |
| **Interview Preference** | Shows deep pointer insight | Safer/cleaner to explain |

### Classic Two-Chain Approach (Easier to Explain in Interviews):
```java
ListNode odd     = head;
ListNode even    = head.next;
ListNode evenHead = even;

while (even != null && even.next != null) {
    odd.next  = even.next;    // odd chain grows
    odd       = odd.next;
    even.next = odd.next;     // even chain grows
    even      = even.next;
}

odd.next = evenHead;          // join: odd tail → even head
return head;
```

> 🎯 **Interview tip:** Start with the classic approach for clarity, then mention the in-place variant as an optimization showing deeper pointer manipulation skills.

## 🔑 Why `even != null && even.next != null`?

```
even != null        →  Needed when list has EVEN length (even lands on null)
even.next != null   →  Needed when list has ODD length  (even.next would be null)

Both checks prevent NullPointerException during:
    odd.next  = even.next       ← needs even != null
    even.next = odd.next.next   ← needs even.next != null
```

Being able to explain **why both conditions exist** is a classic interview follow-up!

## 📌 Key Takeaways (Revision Flashcard)

- 🟡 **`evenHead` never moves** — it's the anchor to rejoin even chain after each odd
- 🟡 **3 pointer ops per step**: skip even for odd → skip odd for even → reattach even chain
- 🟡 **While condition** needs both `even != null` AND `even.next != null` — know why!
- 🟡 **Classic two-chain** is cleaner for interviews; **in-place** shows pointer depth
- 🟡 **Relative order preserved** within odd and even groups — important constraint!
- 🟡 Time: **O(N)** | Space: **O(1)**
