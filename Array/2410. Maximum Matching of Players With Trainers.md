# Match Players and Trainers

## Intuition
We want to maximize the number of players matched with trainers.  
A player can only be matched with a trainer if the trainer’s capacity is **greater than or equal to** the player’s requirement.  
By sorting both arrays, we can greedily assign the smallest available trainer that can handle the current player, ensuring an optimal match.

## Approach
1. Sort both `players` and `trainers` arrays.  
2. Use two pointers (`i` for players, `j` for trainers).  
3. Iterate:
   - If the current player can be matched with the current trainer (`players[i] <= trainers[j]`), increment both pointers and increase the match count.  
   - Otherwise, move to the next trainer (`j++`).  
4. Continue until we reach the end of one of the arrays.  
5. Return the total count of matches.

## Complexity
- **Time Complexity:** `O(n log n + m log m)`  
  - Sorting players (`O(n log n)`) and trainers (`O(m log m)`), where `n` is the number of players and `m` is the number of trainers.  
  - The two-pointer traversal takes `O(n + m)`.  
- **Space Complexity:** `O(1)`  
  - No extra space apart from variables and pointers.

## Code
```java
class Solution {
    public int matchPlayersAndTrainers(int[] players, int[] trainers) {
        Arrays.sort(players);
        Arrays.sort(trainers);

        int count = 0;
        int i = 0; // Pointer for players
        int j = 0; // Pointer for trainers

        while (i < players.length && j < trainers.length) {
            if (players[i] <= trainers[j]) {
                count++;
                i++;
                j++;
            } else {
                j++;
            }
        }
        return count;
    }
}
